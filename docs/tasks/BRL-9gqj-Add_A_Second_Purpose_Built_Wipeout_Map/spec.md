# Outcome

Players queuing or practicing 3v3 Wipeout can get a second accepted layout whose combat rhythm and viable builds differ materially from **Verdant Crossfire** (`verdant-crossfire`, MapPresetId 10), today the only advertised 3v3 Wipeout map.

# Baseline to differ from

Verdant Crossfire is a padded 25×37 portrait sparse recipe on theme 3. It is built almost entirely from green symbol walls (52 cells) and tall grass (46 cells), plus 8 yellow striped cover cells, with three spawns per team at opposite short edges. Its decisions are lane-and-bush: long sightlines along the portrait axis, broken by wall blocks and concealment groups.

The new map must produce visibly different decisions. Examples: wider or landscape proportions, a contested centre with destructible cover, water or barrels that shape routes, shorter sightlines that favour close range, or fewer concealment groups. The final recipe rationale records which differences were chosen and why.

# Scope

- Author one **new** sparse-grid Wipeout recipe with stable identity (next free MapPresetId), three spawns per team, safe re-entry routes, readable bounds, and no mode anchors.
- Do not promote the unadvertised legacy Wipeout recipes (Ashen Court, Barrel Yard, Crossroads Facility, Tidal Garden). They are conversion and proof layouts kept for focused regressions (`docs/16-grid-map-asset-system.md`), at a different scale.
- Use established ground, walls, destructible cover, concealment, barrels, chests, pickups, water, and decoration assets only where they create deliberate decisions.
- Design for at least two viable approaches, meaningful close, mid, and long-range opportunities, limited dead space, and no indefinite disengagement route.
- Advertise it by adding its key to the existing `wipeout-3v3` game type's `maps` list in `config/server/game-types.ron` and bumping that entry's revision. Do not add a new game type: game types already hold several maps, and Practice lets players choose one (BRL-3c10). A new game type would split the 3v3 Wipeout queue.
- Rename the `wipeout-3v3` display name if it still names only Verdant Crossfire.
- Reuse a current presentation theme. A theme different from Verdant's is preferred so the two maps read differently. New gameplay mechanics, assets, and rendering systems are out of scope.
- Update `docs/04-maps-and-game-modes.md`, which lists the advertised 3v3 maps.

# Acceptance criteria

- The recipe resolves and validates. `wipeout-3v3` advertises both maps, and matches on the new map admit, restart, recover, and render through production paths.
- Spawn safety, fighter clearance, projectile readability, Practice bot navigation, destructible state (if used), and the maximum 3v3 performance gate all pass on the new map.
- Matchmade and Practice selection can both reach the new map.
- The recipe rationale (what differs from Verdant Crossfire and why), the evidence, and the durable map documentation are recorded.

# Verification

- `just lint` and `just test`, including the map catalog, validation, and admission tests that cover advertised maps.
- `just practice-e2e wipeout-3v3`, run so that it actually lands on the new map. Extend the script or its selection only if it cannot already target a specific map.
- `just v3-render-evidence`, with `BRAWLER_RENDER_PLAYERS_PER_TEAM=3` and `BRAWLER_RENDER_GAME_TYPE=wipeout-3v3`, on the new map. Attach a top-down capture and a live-match capture.
- A bot-navigation check that every spawn reaches the contested area and both flanks.

# Playtest notes (owner, after done)

This is not a gate for done. The agent fills in the run path and controls when the work lands. The owner plays 3v3 Practice on each map back to back with keyboard and controller, and observes:

- whether range and flank choices feel different from Verdant Crossfire;
- whether either side has a spawn or route advantage;
- whether any spot allows indefinite disengagement.

Feedback goes to this ticket or a new linked ticket.

## Map: **Sluicegate Works** (`sluicegate-works`, MapPresetId 14, MapRecipeId 14)

Decisions — what differs from Verdant Crossfire and why:

- **Landscape 33×25, spawns on the long side ends (left/right).** Spawn-to-spawn distance is 26 cells versus Verdant's 32, so fights start sooner and the rhythm is shorter. Point-symmetric (180° rotation about the centre) so neither side has a route advantage.
- **Theme 1 (facility) with the ground surface and its native kit**: arena walls (asset 2), which render as the facility wall block, and destructible cover (asset 4), which renders as the facility crate. Verdant uses the sand/green-symbol theme 3, so the two maps read differently at a glance, and no 3v3 map used theme 1 before. The catalog lets tall grass grow only on sand, so each grass patch sits on a sand bed (the Feature Yard pattern). Metal walls are sand-only, so they were dropped.
- **Two water canals instead of bush lanes.** Water blocks movement but not projectiles (gameplay profile 5). Each canal splits the map into a centre lane and a flank. Each canal has one 2-cell bridge, offset toward one team (the lower bridge sits on team 0's half, the upper one on team 1's), and the canal ends leave open passages near each base. That gives three routes (centre, lower flank, upper flank), and the canals give mid/long-range trades: you can shoot across water but must walk to a bridge or canal end to commit.
- **Destructible centre.** The centre lane holds an indestructible 3-cell wall pillar that breaks the spawn-to-spawn sightline, surrounded by destructible crates (removed by map-destroying attacks) and two oil barrels. Centre fights are close range, and the cover erodes as the match goes on.
- **Few concealment groups.** Only two tall-grass patches (4×2 cells each, one per flank, at the enemy-side end), 16 cells against Verdant's 46. Concealment is a flank ambush tool, not the default way to travel.
- **Flank incentive.** Each flank has a treasure chest (drops the 40-point restoration pickup) behind a short wall, plus a barrel near the grass. Flanking trades time for sustain.
- **Re-entry.** Each team respawns in a pocket behind a 3-cell shield wall, with exits up, down and straight ahead, so a respawning fighter picks a lane instead of walking straight into one sightline. No mode anchors.
- **Close/mid/long.** Close: centre cover, flank wall stubs, grass. Mid: across the canals and lane diagonals. Long: the open canal rows and the outer flank rows (y=2/22) between wall stubs.
- No new assets, mechanics or rendering. Only existing assets 1 (ground), 2 (wall), 4 (crate), 5 (sand bed), 6 (water), 8 (grass), 20 (spawn), 24 (barrel), 26 (chest).

# Learnings

- **Mistake:** I first authored the map with metal walls, green striped cover and tall grass on the ground surface. Embedded catalog resolution refused it with "placement is incompatible with the effective surface", because tall grass and the metal/wood/symbol/brick walls allow only the sand surface tag, while barrels and chests allow only ground. **Cause:** I picked assets by look before reading `allowed_surface_tags` in `content/catalogs/map_assets.ron`. **Prevention:** choose a theme's surface first, filter assets by `allowed_surface_tags`, and prefer the theme kit's own pieces (`assets/catalogs/map_asset_visuals.ron` `theme_kits`). The kit audit test also checks this.
- A new built-in map touches several goldens on purpose: the map compatibility digests (`src/map/compatibility_tests.rs`), the lobby catalog revision and Practice map lists (`src/server/lobby/catalog.rs`), the theme-kit coverage count (client `environment_assets/catalog.rs`), and the shell overview art check. Expect them and update them in the same change.
- Practice automation had no map selection, so a second map in a game type was unreachable by `practice-e2e`. The bounded `--product-practice-map` flag now fails the smoke if Active lands on the wrong recipe.
